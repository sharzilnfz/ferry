# Ticket T-14 Completion Report: Retire CLI M0 Stack

## Summary
Ticket T-14 retired the hand-rolled M0 exchange loop and custom wire protocol machinery from `ferry-cli`, replacing them with `ferry_sync::SyncEngine`. Both `ferry daemon` and `ferry sync` now drive `SyncEngine` directly across standard seams (`Transport` / `TcpTransport`), achieving parity with `ferry-daemon` and removing 941 lines of duplicate protocol code.

## Key Changes
1. **`ferry-cli/src/commands/daemon.rs`**: Replaced manual `WatchedFolder`, `spawn_accept_loop`, `serve_session`, and `spawn_dial_loop` with `SyncEngine::new(cfg, transport)`. Configures listener, dials peer if specified, and joins cleanly until process signal.
2. **`ferry-cli/src/commands/sync.rs`**: Converted to drive `SyncEngine` with `poll_interval: 50ms` and `opportunistic_every: 1` until agreement is settled or timeout expires, returning the documented JSON / human format and exit codes (0 for converged, 1 for timeout).
3. **`ferry-cli/src/exchange.rs`**: Completely deleted (564 lines of duplicate M0 protocol logic removed). Removed `pub mod exchange;` from `crates/ferry-cli/src/lib.rs`.
4. **`ferry-cli/Cargo.toml`**: Removed unused `blake3` direct dependency from `ferry-cli`.
5. **Folder & Store Harmonization**: Configured `ferry-cli` store bootstrap and `snapshot_dir` to share store exclusion (`.ferry`) and default ignore rules (`ferry.ignore` / `DEFAULT_IGNORE`), ensuring seamless interoperability between `ferry init`/`pair` and `SyncEngine`.
