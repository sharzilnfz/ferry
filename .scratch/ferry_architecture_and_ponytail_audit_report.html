1. The Evolutionary Journey: Where We Started vs Where We Are Now

Ferry was engineered to solve the full-file sync problem for developer directories (node_modules, .env, build caches, and AI agent memory) that Git refuses to carry. The architecture evolved through four decisive phases:

Epoch 1: Inception M0 / v0

Prototyping & Early v1

  • Dual sync loops (ferry-cli/exchange.rs vs ferry-sync).
  • InlineMaterializer allowed untrusted symlinks to escape sync root.
  • 8-mutex Ctx god-struct with racing session adoptions.
  • Un-debounced 200ms thread::sleep polling loop.
  • Default TOFU (Trust On First Use) security vulnerability.
Status: Functional but fragile & leaky
Epoch 2: Hardening arch-hardening

20 Correctness Tickets

  • Deleted InlineMaterializer (~700 LOC); enforced Applier.
  • Bounded memory parsing (ValidatedPoly, 256 KiB streaming I/O).
  • Poison-tolerant locks across daemon and iroh.
  • Atomic create-exclusive quarantine landing.
  • Windows path colon/prefix sanitization.
Status: Concurrency & memory safety solved
Epoch 3: Deepening arch-deepening

Deep Seams & ADR-0007

  • Encapsulated pinning behind deep PinManager.
  • Noise handshake wrapped in SecureSession.
  • Single Store-opening interface in ferry-folder.
  • Two-sided ancestor reconciliation with empty-base fallback.
  • Enacted ADR-0007: Refuse-by-default peer trust.
Status: Clear domains & trust boundaries
Epoch 4: Deep Sync deep-sync (HEAD)

Consolidated Sync & IPC

  • Embedded ScanEngine in SyncEngine with event debouncing.
  • FerryIgnore bound authoritatively at scan seam.
  • Transactional pinning in ConvergenceEngine.
  • Self-healing FolderEngine with broadcast events.
  • Universal AutoBackend in ferry-ipc.
Status: Fully integrated, zero idle spin

4. Deep Module Analysis (Interface Simplicity vs Engine Power)

Per John Ousterhout's A Philosophy of Software Design and Poteto's model-the-domain, deep modules provide simple, narrow interfaces that hide massive internal complexity.

✔ Exemplary Deep Modules (Preserve & Cherish)
ferry-store::Store
Interface: put_data, get, adopt_pack.
Hidden Engine: FastCDC chunker, 8 CSPRNG staging pools, pack sealing, BLAKE3 authentication, incremental single-pack indexes, compaction.
ferry-materialize::Applier
Interface: Applier::new().apply_change_set(&cs).
Hidden Engine: Case folding, anti-TOCTOU live tree verification, atomic temporary writes, hash pre-verification, directory mtime restoration.
ferry-sync-engine::ConvergenceEngine
Interface: converge(local, remote, base).
Hidden Engine: 3-way reconciliation, deletion resurrection, pin rule matching, loser quarantine creation, agreement ledger commit.
⚠ Shallow Modules & Wrappers (Eliminate)
ferry-pin (Facade Crate)
Flaw: Shallow pass-through crate re-exporting symbols from ferry-sync-engine.
Resolution: Dissolve crate; move directly into ferry_sync_engine::pin.
ferry-daemon::ui::backend (3 Adapters)
Flaw: AutoBackend, DirectBackend, InProcessAdapter triplication (1,245 LOC).
Resolution: Consolidate onto single parameterized FolderBackend<StateSource>.
GLOBAL_DIRECTORY (OnceLock in iroh)
Flaw: Dual state truth with instance Inner.routes causing split-brain routing.
Resolution: Delete global static; pass routes strictly via IrohConfig.
