# T-013: CLI surface

Status: done
Depends on: T-006, T-007, T-010

`ferry init | add | pair | share | status | conflicts list | ignore | daemon`.
Daemon mode = watch + continuous sync + LAN/relay connectivity. Single-shot
`ferry sync` for scripting. Output is machine-parseable with `--json`.
Install path: one-line script (curl | sh) plus Homebrew formula later;
Windows via cargo-installed binary initially.

Acceptance: from zero to two synced machines using only `--help`, in under
five minutes, on each OS (manual checklist scripted where possible).

### FERRY_HOME contract

`FERRY_HOME` overrides `~/.ferry` for ALL per-device state; empty string is
treated as unset. Identity lives at `<home>/identity/device.key`. This is
the device-isolation seam the quickstart script uses for two simulated
devices on one host. Per-folder state follows docs/store-format.md:
`.ferry/config` (CONFIG_HEAD), plus CLI-owned `.ferry/settings.json`
(ignore layers), `.ferry/peers/<hex>.agreed` (+ `.addr` reachability hints
written after successful dials), `.ferry/conflicts.jsonl`.

### Daemon honesty notes (what it really does today)

- Watching is ferry-scan's ScanEngine (native events, poll fallback,
  audits); every CLI scan path (status/sync/exchange rounds) goes through
  the same policy-aware pipeline, so ignore rules and `.ferry` exclusion
  behave identically everywhere.
- Exchange speaks ferry-sync's M0 message inventory
  (HELLO/OFFER/REQ_META/REQ_DATA/ITEM) over the existing Transport seam,
  strictly alternating dialer/listener script; blobs move individually and
  are hash-verified before storage.
- ONE peer via explicit `--peer-url`; the listener side routes sessions by
  the folder half of the HELLO tag (`ferry-<dev8>-<folder8>`).
- Reconcile is three-way (ferry-sync-engine) against the last-agreed base;
  conflicts quarantine loudly per ADR-0004. Agreement = min(manifest ids)
  recorded when an OFFER shows equal roots; both sides derive it
  identically.
- Semantic edge worth knowing: DELETIONS propagate only relative to a
  recorded agreement. Before the first settle, "present on one side only"
  resolves as add (presence wins) — the safe default; the quickstart
  script waits for the first agreement before mutating.
- The store is sealed (flush + index snapshot) at every round end so
  agreement bases survive restarts.

### Transport stub status

`--transport tcp` works today. Any other value (e.g. `iroh`) fails cleanly
with code `transport-unavailable` pointing at T-009/T-014; no partial or
silently-degraded behavior.

### Acceptance result

scripts/quickstart-e2e.sh automates the verbatim acceptance on one machine
(two FERRY_HOMEs/trees/ports): secret gate refuses a flagged .env loudly
(redacted) → share emits offer+code+QR → payload files carry the ritual to
device B → daemons converge byte-for-byte (incl. exec bit, late edits,
deletion propagation) with .env kept local → conflicts.jsonl empty →
agreement pointers visible in status. Wall time ~4–6 s (budget 300 s);
portable macOS bash 3.2 / GNU/Linux. docs/quickstart.md is the human twin
of the same flow, honest about single-machine simulation vs true P2P
(pending T-009/T-014).

### Tests + gates

### Deviations from ticket text (all additive)

- `pair --accept` takes an optional destination dir (defaults to cwd); a
  folder must exist somewhere for B to materialize into.
- `conflicts list` takes the folder as cwd (consistent with ignore/status)
  rather than a positional argument.
- `ferry sync` requires `--peer-url` (no discovery exists yet).
