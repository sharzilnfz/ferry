Architectural Hardening & Seam Unification

From Prototype to Production-Grade Modular Sync

Ferry is evolving from a single-process prototype to a hardened, deeply modular peer-to-peer sync engine. This blueprint specifies the replacement of fragmented UI adapters with a single deep trait (UiBackend), the introduction of an ultra-lightweight pure-Rust GUI (ferry-gui via egui), complete compile-time stripping of unused frontends, and event-driven push streaming for true 0.0% idle CPU utilization.

Core Seam & Contract Definition

The Unified `UiBackend` Trait

In accordance with Michael Feathers and John Ousterhout deep-module principles, the interface is narrow, stable, and returns typed domain objects. Two concrete adapters satisfy this interface: DaemonIpcAdapter (remote over domain sockets / named pipes) and InProcessAdapter (in-memory invocation).

crates/ferry-ui-core/src/backend.rs 
use std::path::{Path, PathBuf};
use std::pin::Pin;
use std::future::Future;
use tokio_stream::Stream;
use ferry_ipc::{EngineSnapshot, ConflictEntry, PinRecord};

pub type BoxFuture<'a, T> = Pin<Box<dyn Future<Output = T> + Send + 'a>>;
pub type UiEventStream = Pin<Box<dyn Stream<Item = UiEvent> + Send + 'static>>;

/// Unified deep trait powering all Ferry frontends.
pub trait UiBackend: Send + Sync + 'static {
    /// Current engine snapshot (files, chunk counts, peers, conflicts).
    fn get_status(&self) -> BoxFuture<'_, Result<EngineSnapshot, OpError>>;

    /// List all quarantined conflicts in `.ferry/conflicts.jsonl`.
    fn list_conflicts(&self) -> BoxFuture<'_, Result<Vec<ConflictEntry>, OpError>>;

    /// Session pinning controls.
    fn start_pin(&self, paths: Vec<String>, hours: Option<u64>) -> BoxFuture<'_, Result<PinRecord, OpError>>;
    fn stop_pin(&self) -> BoxFuture<'_, Result<PinStopSummary, OpError>>;
    fn release_pin(&self) -> BoxFuture<'_, Result<PinReleaseSummary, OpError>>;

    /// Pairing & secret scan operations.
    fn share_initiate(&self, folder: Option<PathBuf>, i_know: bool) -> BoxFuture<'_, Result<ShareOffer, OpError>>;
    fn share_status(&self, folder: Option<PathBuf>) -> BoxFuture<'_, Result<ShareStatus, OpError>>;
    fn pair_accept(&self, payload: PathBuf, dir: Option<PathBuf>) -> BoxFuture<'_, Result<PairResult, OpError>>;

    /// Trigger manual audit rescan of the directory.
    fn trigger_scan(&self) -> BoxFuture<'_, Result<(), OpError>>;

    /// Real-time 0.0% idle CPU push event stream.
    fn subscribe_events(&self) -> BoxFuture<'_, Result<UiEventStream, OpError>>;
}

/// 1. DaemonIpcAdapter: Communicates over Unix Socket / Named Pipe
pub struct DaemonIpcAdapter {
    socket_path: PathBuf,
}

impl DaemonIpcAdapter {
    pub fn new(socket_path: PathBuf) -> Self {
        Self { socket_path }
    }
}

/// 2. InProcessAdapter: Direct in-memory engine execution
pub struct InProcessAdapter {
    folder: PathBuf,
}

impl InProcessAdapter {
    pub fn new(folder: PathBuf) -> Self {
        Self { folder }
    }
}

/// 3. AutoBackend: Transparent daemon detection + local fallback
pub struct AutoBackend {
    ipc: DaemonIpcAdapter,
    local: InProcessAdapter,
}

impl UiBackend for AutoBackend {
    fn get_status(&self) -> BoxFuture<'_, Result<EngineSnapshot, OpError>> {
        Box::pin(async move {
            if let Ok(snap) = self.ipc.get_status().await {
                return Ok(snap);
            }
            // Daemon offline: direct in-process scan
            self.local.get_status().await
        })
    }
    // ... all other methods delegate cleanly ...
}
Adapter Execution Dynamics
Runtime Seam

When ferry daemon is active, all frontends connect via DaemonIpcAdapter, receiving instant notifications with 0 disk re-scanning overhead. When the user runs ferry ui or ferry status standalone without a daemon, InProcessAdapter executes direct one-shot scans via ferry-folder without duplicating code.

crates/ferry-cli/src/commands/ui.rs 
pub struct UiArgs<'a> {
    pub folder: Option<&'a Path>,
    pub frontend: FrontendKind, // Web, Gui, Tui
    pub host: &'a str,
    pub port: u16,
    pub no_open: bool,
}

pub fn run(args: UiArgs) -> CliResult<Output> {
    match args.frontend {
        FrontendKind::Gui => {
            #[cfg(feature = "gui")]
            {
                ferry_gui::launch_native_gui(args.folder)
            }
            #[cfg(not(feature = "gui"))]
            {
                return Err(CliError::feature_disabled("gui"));
            }
        }
        FrontendKind::Tui => {
            #[cfg(feature = "tui")]
            {
                ferry_tui::launch_tui(args.folder)
            }
            #[cfg(not(feature = "tui"))]
            {
                return Err(CliError::feature_disabled("tui"));
            }
        }
        FrontendKind::Web => {
            #[cfg(feature = "web-ui")]
            {
                run_web_ui_server(args)
            }
            #[cfg(not(feature = "web-ui"))]
            {
                return Err(CliError::feature_disabled("web-ui"));
            }
        }
    }
}

use egui::{Color32, Pos2, Rect, Response, Sense, Ui, Vec2};

pub fn render_beacon(ui: &mut Ui, color: Color32, pulsing: bool) -> Response {
    let (rect, resp) = ui.allocate_exact_size(Vec2::splat(24.0), Sense::hover());
    if ui.is_rect_visible(rect) {
        let painter = ui.painter();
        let center = rect.center();
        let time = ui.input(|i| i.time);
        
        // Outer pulsing aura
        if pulsing {
            let wave = ((time * 2.5).sin() * 0.5 + 0.5) as f32;
            let radius = 6.0 + wave * 4.5;
            let alpha = ((1.0 - wave) * 90.0) as u8;
            painter.circle_filled(center, radius, Color32::from_rgba_unmultiplied(color.r(), color.g(), color.b(), alpha));
        }

        // Inner solid core
        painter.circle_filled(center, 4.5, color);
    }
    resp
}

Event-Driven Push Architecture

Eliminating Polling for True 0.0% Idle CPU

The previous prototype in crates/ferry-daemon/src/ui/server.rs used a 1-second interval timer that repeatedly queried state and ran string diffs. We replace this with native push subscriptions over Tokio broadcast channels, waking threads only when actual filesystem or sync state changes occur.

⚡ Push Notification Sequence
Zero Wakeups
  1. Filesystem Mutation: ferry-scan detects tree change via native OS event (kqueue/inotify/ReadDirectoryChangesW).
  2. Engine Transition: EngineHandle updates active manifest ID & chunk counts.
  3. Broadcast Dispatch: DaemonState::broadcast() emits a lightweight DaemonMessage::StateChanged.
  4. Zero-Copy Stream: UiBackend::subscribe_events() forwards the message directly to:
    • Axum SSE stream (/api/events)
    • egui repaint request handle
    • ratatui terminal redraw event loop
  5. Idle State: When no events occur, all UI threads sleep on OS socket selectors (0.00% CPU).

// ❌ BEFORE: 1-second Polling Loop (High CPU & Battery Drain)

// ✅ AFTER: Event Push Subscription (0.0% Idle CPU)
async fn api_events(
    State(server): State<DashboardServer>,
) -> Sse<impl tokio_stream::Stream<Item = Result<Event, Infallible>>> {
    let stream = server.backend.subscribe_events().await
        .unwrap_or_else(|_| Box::pin(tokio_stream::empty()));

    let mapped = stream.map(|evt| {
        let payload = serde_json::to_string(&evt).unwrap_or_default();
        Ok(Event::default().event("state").data(payload))
    });

    Sse::new(mapped).keep_alive(KeepAlive::default())
}
